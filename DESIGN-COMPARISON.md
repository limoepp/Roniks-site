# Две версии дизайна «Роникс»

- `main`: текущий дизайн, основа для сравнения.
- `design/keri-style`: вариант, приближённый к оформлению клиники «Кэри».
- `mvp-original`: тег исходного состояния при добавлении проекта в Git.

Ветка `design/keri-style` первоначально совпадает с `main`. Визуальные изменения в ней ещё не выполнены.

## Как сравнивать

Для заказчика удобнее две отдельные демоссылки на одинаковые страницы, чем переключение веток в Git. Существующая ссылка показывает текущий дизайн:
https://roniks-mvp-review-131126.lucidglass8.chatgpt.site/

Вторую демоверсию следует публиковать отдельно после подготовки нового дизайна, сохраняя первую. Использовать одинаковые цены, тексты, акции и фотографии, чтобы отличалось именно оформление. После выбора объединить согласованный вариант в `main` через pull request, а исходный вид сохранить тегом.

Порядок работы: сначала сравнить страницу «Цены», затем распространить выбранное оформление на главную и остальные страницы. Дать заказчику одинаковые задания: найти маникюр, определить цену, посмотреть акцию, открыть запись. Собрать замечания: страница → проблема → желаемый результат → важность.

Это сравнение вариантов дизайна. Статистический A/B-тест с распределением реальных посетителей на стадии согласования не нужен.

## Что хранится в Git

В Git входят PHP-код, CSS/JS, шрифты, общедоступный прайс и акции, пример настроек. Рабочие настройки, пароль администратора, ключи, заявки, резервные копии, мастера/галерея и загруженные изображения остаются локальными. Их нужно переносить и резервировать отдельно при размещении рабочего сайта.

После клонирования запустить `php -c php-local.ini scripts/setup.php`: появятся отсутствующие настройки, пустые данные и случайный первоначальный пароль. Уже существующие файлы не заменяются. При первом входе в админку сменить временный пароль.

Переключение ветки само по себе не обновляет опубликованную демоверсию и не переключает отдельную базу содержимого: обе локальные ветки используют игнорируемые файлы data/ текущего каталога. Для одновременного локального запуска двух версий нужны отдельные рабочие каталоги и порты.
