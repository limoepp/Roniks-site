# Демонстрация и запись

## Безопасное повторение
1. Прочитать STATUS и проверить ветку/чистоту Git. A хранится в main, B — в design/keri-style. Не переключать ветку с несохранёнными изменениями.
2. При необходимости создать отдельную рабочую копию и выполнить `scripts/setup.php`. Локальные настройки и JSON вне Git остаются на диске при переключении веток.
3. Проверить PHP и публичные страницы локально. Не выводить пароли, настройки и заявки в логи.
4. На ветке B выполнить экспорт в новую папку вне PHP-проекта:

```powershell
python scripts/export-demo.py --output C:\path\to\new-demo --host roniks-keri-design-131126.lucidglass8.chatgpt.site
```

Указать доступный Python 3 и PHP (`--php C:\php\php.exe` при необходимости). Используется локальный php-local.ini. По умолчанию памятка берётся из docs/CLIENT-REVIEW.md; `--guide` принимает готовый HTML. Экспорт берёт текущие локальные публичные данные, поэтому перед публикацией сверить их с утверждённым содержимым.

Скрипт создаёт `dist/`, копирует assets и только упомянутые в страницах изображения из uploads. Служебные data, админка, заявки и секреты не копируются. Форма записи заменяется пояснением, звонки и мессенджеры блокируются demo.js. GET-поиск по ценам остаётся рабочим; прочие формы останавливают экспорт. Непустой существующий dist не перезаписывается: использовать новую папку, чтобы исключить старые файлы. Демо содержит noindex и robots Disallow; это не ограничение доступа.

## Публикация
У каждой версии собственный Sites project_id (в STATUS). Сохранять `.openai/hosting.json` с правильным project_id и `static.directory: dist`. Не копировать manifest A в B. Через skill Sites использовать source helper: краткоживущие credentials только в памяти и stdin, без файлов и аргументов команд. После подтверждённого push передать точный commit_sha и архив в save_site_version, затем deploy_site_version. Зафиксировать успешный URL, saved version и deployment в STATUS.

На Windows helper с tty может вывести путь архива и ждать закрытия stdin. В проверенной сессии Ctrl+Z + Enter завершили ввод; после этого получен итоговый JSON и exit 0. Не считать один путь архива доказательством успешного окончания.

После публикации проверить прайс, поиск, окно записи и узкий экран. PHP-админка не обновляет снимок Sites автоматически: нужен новый экспорт/публикация. Публичность ссылки согласована пользователем; сохранять эту аудиторию для текущих демо.

## Сценарий ролика B
1. Главная: палитра, шапка, поиск, блок акций.
2. Прокрутка к направлениям услуг.
3. Цены: боковое меню, варианты по длине волос.
4. Выбор «Ногтевой сервис», поиск «маникюр».
5. Открытие и закрытие демонстрационного окна записи.
6. Акции, затем контакты без реального звонка или отправки данных.
7. Возврат на главную и остановка записи.

OBS: сцена «Роникс — запись сайта», источник «Браузер», URL опубликованного варианта, 1920×1080. Источник показывает только страницу; рабочий стол, уведомления и камера не входят в кадр. Микрофон и системный звук заглушить. Убрать cookie-уведомление до старта. Управлять страницей через «Взаимодействовать»; закрытие этого окна не останавливает запись.

После остановки дождаться «Запись сохранена» и кнопки «Начать запись». Скопировать/ремультиплексировать видео в outputs чата, исключив все аудиопотоки. Проверить разрешение, длительность, отсутствие аудио и кадры из разных частей ролика. У B проверено 6 кадров (5, 18, 29, 37, 57, 70 секунд). Во время записи OBS кратко показывал предупреждение о перегрузке кодировщика; полный проход успешно декодировал 5764 кадра, максимальный интервал между кадрами — 0,0334 с. Выбранные кадры читаемы.
